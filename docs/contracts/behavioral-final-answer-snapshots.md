# Behavioral Final Answer Snapshots

A completed behavioral attempt owns an immutable `finalAnswerSnapshot`. It is
the exact standalone answer produced for that attempt, not a pointer to the
current canonical Solution Profile. Past, coordinator Markdown, and local HTML
or JSON export project the same stored snapshot.

## Version 1

Every new completed behavioral finalization supplies:

- one stable `finalAnswerOperationId` for exact retry;
- `schemaVersion: 1` and the exact answer, byte-identical to `modelAnswer`;
- `scope: universal | target_tailored`;
- the stable question ID plus the title and prompt as evaluated;
- the exact Solution Profile question and revision linked to the attempt;
- an optional stable story/alternative identity when that domain has produced
  one;
- accepted supporting evidence IDs, evidence gaps, and contradictions;
- the exact owner-scoped behavioral specialist response turn containing the
  answer;
- for `target_tailored`, the exact Target Profile ID, revision, display label,
  and bounded competency emphasis—never a raw JD, source locator, or target
  analysis.
- the typed attempt audit defined by `behavioral-attempt-analysis.md`.

The response turn may follow a typed or Voice-managed user answer. D1 verifies
the same activity transcript, accepted question evidence, and linked Solution
Profile revision in the final write transaction.

## Immutability and corrections

The first snapshot is revision 1. An exact operation retry returns the original
revision without rewriting it. Changed content requires a new operation ID and
`finalAnswerCorrection` naming the current `replacesSnapshotRevision` plus a
reason. D1 appends the next revision; every earlier revision remains readable.
A stale correction, changed operation retry, or silent replacement is rejected.

Corrections reset the specialist finalization to ready for publication. They do
not mutate an already merged historical artifact in place; the coordinator
publishes a new artifact revision through the normal workflow.

## Parent-domain boundaries

- Issue #201 owns typed Behavioral Attempt analysis and Story Bank identities.
  `story` remains optional until that domain returns an authoritative identity.
- Issue #209 owns Target Profiles, immutable target revisions, bindings, and
  preflight. `target_tailored` finalization must use the exact target returned
  by the current `finalization` preflight; callers must not invent a target
  revision or downgrade the answer to universal.
- Issue #226 owns this snapshot, correction, projection, and reader contract.
  Refinements belong there or in a linked child issue, not by rewriting the
  historical parent descriptions.

## Readers and legacy records

Past renders **Final tailored answer** as its own section after Conversation
and separately from Review. Problem Bank attempt links open that exact
activity, so the historical snapshot is not replaced by the current canonical
profile. Coordinator reads include the stored projection plus Markdown and
HTML generated by one renderer. Export today embeds those same server-rendered
values.

Older behavioral finalizations with only `modelAnswer` remain readable as an
explicit `legacy_model_answer` fallback. They receive no fabricated snapshot,
revision, evidence, story, target, or backfill.
