Corrected product boundary

Three questions.Three systems.

Private interview evidence, ordinary Loop operations, and a website-wide AI assistant are independent capabilities. They can share foundations without owning one another.

The previous approach was false.

It visually and conceptually centered AI around Loops, making recording upload and Loop creation look like AI features. This revision removes that coupling.

Create and manage a Loop

Use a normal website form to create the Loop, Role Brief revision 1, initial stages, provenance, and a stable command receipt atomically.

Ask Interview Arc anywhere

Authentication, D1, R2, receipts, traces, and UI primitives can be reused. Product ownership and release dependencies remain separate.

Issue #415 · Private evidence

How do I upload my recording and transcript?

The owner explicitly chooses files through the website. Interview Arc creates an interview-evidence package, verifies every asset, stores private source bytes in R2 and authoritative metadata in D1, and lets the owner attach the package to a Loop/Round.

Current

No website upload path

Interview Arc does not currently ingest an arbitrary local folder, recording, or transcript. A local folder remains private and untouched.

Target

Explicit browser upload

Open a Loop/Round or the unassigned evidence inbox, choose files, review their relationships, upload, validate, and finalize.

Select

Choose audio and TXT, VTT, or SRT transcript files through the browser picker.

Review

Confirm safe names, types, bytes, checksums, interview time, timezone, and relationships.

Upload

Stream or resume each asset with server-recorded progress and visible per-file state.

Finalize

Reconcile checksum, signature, D1 metadata, R2 source bytes, and authorized readback.

Assign

Attach to an exact Loop/Round now, reassign later, or keep it in the unassigned inbox.

Use

Read the supplied transcript and play or download authorized audio.

Correct

Create traceable transcript or metadata revisions without replacing the source.

Delete

Run separately confirmed, governed deletion with visible reconciliation state.

No hidden folder scan. The browser never sends an absolute filesystem path, and the server never scans a local directory. The owner makes an explicit selection. Display filenames never become R2 object keys.

Package authority

  • D1 owns package and asset state
  • One event may contain multiple assets
  • Assignment can be absent or revised
  • Every mutation is idempotent

Private object storage

  • R2 begins in quarantine
  • Opaque owner and asset keys only
  • Checksum and signature verification
  • D1-authorized range reads

Transcript fidelity

  • Original bytes and digest preserved
  • Deterministic TXT/VTT/SRT parsing
  • No invented speakers or timestamps
  • No AI/provider submission in #415

Privacy and consent

  • Owner affirms permission to store/process the recording
  • Content, names, paths, IDs, and object keys stay out of public logs
  • Cross-owner reads, ranges, assignment, and deletion are denied
  • Retention and export behavior are owner-visible before release

Release gates

  • Interrupted upload and exact retry
  • Malformed, mislabeled, oversized, and truncated files
  • D1-only, R2-only, corrupt, and partial-delete reconciliation
  • Keyboard, screen reader, mobile, zoom, and large-manifest E2E

Issue #417 · Loop operations

How do I actually add a Loop?

Today, the long-lived Loop Recorder task is the supported mutation path. The target is an ordinary Add Loop screen backed by one deterministic domain command. AI is neither required nor embedded.

Current path

Use the Loop Recorder

Provide company, role, job-description text or source, location and opened date when known, stages and dates, statuses, and explicit unknowns.

Website path

Choose “Add Loop”

Enter facts, preserve unknowns, review the exact initial record, create atomically, receive a receipt, and open the new Loop.

01 · EnterKnown facts

Company, role, source, location, opened date, and known stages.

02 · MarkUnknowns

Absence stays explicit. The product does not infer missing facts.

03 · ReviewExact creation

Loop, Role Brief revision 1, stages, provenance, and warnings.

04 · ApplyOne transaction

Validation and domain invariants run before an atomic commit.

05 · ReceiveStable receipt

Exact retries return the same result; conflicts preserve the form.

Manual website form ─┐ Loop Recorder ───────┼──▶ create_loop command ──▶ Loop + Role Brief revision 1 Future AI proposal ──┘ │ └─────────────▶ receipt / typed conflict Business invariants live in create_loop, not in any adapter.

Atomic domain change

Loop, Role Brief revision 1, initial stages, source provenance, and receipt commit together or not at all.

Idempotent retry

The owner, command version, idempotency key, and canonical request digest bind one stable result. Changed input produces a typed conflict.

Separate adapters

The website and Loop Recorder authenticate differently but reuse one command. Neither can impersonate the other.

Relationship to AI: the site-wide assistant may later propose a filled create_loop payload. The owner must review it, and approval calls the same deterministic command. Turning AI off does not remove Add Loop.

Issue #418 · Horizontal platform capability

How does AI belong on the website?

As “Ask Interview Arc” in the shared application shell—not inside Loops. It understands the current workspace, uses only explicitly selected context, and joins domains through reviewed read and command adapters.

Available from every authenticated workspace

One assistant shell. Many domain-owned capabilities.

The shared platform owns conversation, context minimization, provider routing, proposal integrity, approval, retention, cost controls, and safe observability. Each product domain retains its own authorization, schemas, citations, commands, and invariants.

Mode 1

Read and explain

Retrieve selected owner-authorized records through read adapters, answer with citations, and distinguish verified facts, model inference, conflicts, and unknowns. No mutation tools exist in this mode.

Emit one versioned, allowlisted proposal. Deterministic code validates and freezes it. The owner edits, approves, or rejects the exact revision and digest before an owning domain command runs.

Context safety

  • Typed references, not opaque page dumps
  • Owner authorization on every resolution
  • Explicit selection and sensitivity labels
  • Citation and revision receipts

Action safety

  • Server-owned command allowlist
  • Immutable versioned proposal digest
  • Single-use approval and stale-state conflict
  • No generic AI write or SQL path

Operational safety

  • Manual website remains available
  • Visible retention and deletion controls
  • Timeout, cancellation, budgets, circuit breaker
  • Public-safe traces without prompts or IDs

Prompt injection boundary: job descriptions, URLs, published pages, transcripts, code, and model output are untrusted data. They cannot add context, name a new adapter, expand a schema, change retention, or grant authority.

Delivery plan

Ship three vertical slices, then connect adapters.

A vertical slice is an independently useful end-to-end path. Each issue owns its own implementation worktree, PR, tests, Engineering receipt, production verification, and cleanup.

Track B · #417

Deterministic Add Loop

Extract the shared command, retain Loop Recorder compatibility, add the website adapter and form, then verify atomicity, authorization, accessibility, and E2E recovery.

Track A · #415

Evidence package path

Implement manifest, quarantine upload, validation, D1/R2 reconciliation, assignment/unassigned inbox, reading, revision, and governed deletion. Decide limits and retention before release.

Track C · #418

Site-wide assistant

Start with shared shell and read-only published grounding, prove a second workspace, then add proposal/approval around existing commands. Private evidence comes only after separate policy approval.

Decisions for #415

  • Audio and transcript format/size allowlists
  • Retention, download, export, and tombstones
  • Scanning requirement and transcript-body storage threshold

Decisions for #418

  • Provider, model routing, retention, regions, and budgets
  • First two read adapters and first two command domains
  • Conversation history/export/deletion policy

What this design PR does: corrects capability ownership, publishes the plan and source diagrams, and links the three issues. It does not implement, migrate, ingest real files, merge, or deploy.
