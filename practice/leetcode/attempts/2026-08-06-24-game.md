# 24 Game

## Pinned Notes

- Canonical numeric-state memoization

- Memoize the complete current state, not only the most recent choice. For an unordered number pool, sort it so equivalent permutations share one canonical key.
- In an existential search with a fixed target, a dead-state `HashSet` is sufficient: cache a state only after every branch fails. Successful states return immediately.
- Never hash raw `double` values when mathematically equivalent computations may produce slightly different bits. Compare target values with an epsilon.
- Fixed-decimal strings and integer quantization solve the same approximate canonicalization problem. `String.format(Locale.ROOT, "%.10f", value)` is readable; `Math.round(value / EPS)` produces a faster, locale-independent integer bucket. Both intentionally merge values within a chosen tolerance.
- A sorted immutable `List<Long>` works as a key because Java `List.equals` and `List.hashCode` are content- and order-based. Never mutate a collection after inserting it into a hash-based set or map. Java arrays use identity equality unless wrapped or handled explicitly.
- For exact arithmetic, represent each value as a reduced rational `(numerator, denominator)`: keep the denominator positive and divide both fields by their greatest common divisor after every operation. Exact success is `numerator == target * denominator`, with no epsilon. Use `BigInteger` if generalized inputs can overflow `long`.
- Practical choice: for four-card 24 Game, prefer `double` plus epsilon and usually omit memoization; for larger approximate searches, use sorted quantized buckets; for exact generalized searches, use sorted reduced rationals.
